# 3. Реализация

## 3.1. Стек и объём

.NET 10, ASP.NET Core minimal API, EF Core и SQLite, xUnit v3, Tesseract 5
через командную строку, Docker и GitHub Actions ([`SPEC.md`](../../SPEC.md),
[`EasyLangApi.csproj`](../../EasyLangApi.csproj)).

Объём на коммите `cd78dfc` (подсчёт `wc -l` по файлам из `git ls-files`):
приложение — 54 файла `*.cs`, 2711 строк без миграций; тесты — 2318 строк.

## 3.2. Поток разбора фразы

`GET /lines/{id}/explain?phrase=...` ([`Lookups/LookupService.cs`](../../Lookups/LookupService.cs)):

1. найти реплику (фильтр по владельцу добавит EF), иначе 404;
2. проверить суточную квоту разборов;
3. собрать контекст: название эпизода, говорящий из префикса `ИМЯ:`, две
   реплики до и две после — одним запросом по индексу `(EpisodeId, Index)`;
4. спросить `IPhraseExplainer`;
5. найти или создать `KnowledgeItem` по нормализованной фразе и записать
   `Lookup` одной транзакцией.

Если внешний сервис недоступен, исключение вылетает до записи — ничего не
сохраняется, клиент получает 503.

## 3.3. Объяснение фразы

**Словарь** ([`Explaining/DictionaryExplainer.cs`](../../Explaining/DictionaryExplainer.cs)) —
dictionaryapi.dev, без ключа. Контекст словарь не понимает, поэтому
используется только для сортировки значений: первым идёт то, у которого
больше общих слов со сценой. Выражения, которых нет в словаре, разбираются по
отдельным словам с пометкой `found = false`.

**Языковая модель** ([`Explaining/LlmExplainer.cs`](../../Explaining/LlmExplainer.cs)) —
любой API, совместимый с OpenAI Chat Completions: адрес, модель и ключ задаются
в конфигурации, поэтому подходит и облачный сервис, и локальная Ollama.
Промпт ([`Explaining/PromptBuilder.cs`](../../Explaining/PromptBuilder.cs)) просит
объяснить фразу «как она сказана в этой сцене, а не по словам» и вернуть JSON
с переводом, смыслом, частью речи, пометкой о контексте и примером. Блоки
контекста добавляются, только если для них есть данные; без контекста модель
просят дать самое частое значение. Разбор ответа
([`Explaining/LlmResponseParser.cs`](../../Explaining/LlmResponseParser.cs))
терпим к нарушению формата: берётся первый объект `{...}`, а если JSON не
разобрался, текст ответа сохраняется целиком.

## 3.4. Распознавание текста

`POST /recognize` ([`Recognition/`](../../Recognition/)) проверяет формат по
сигнатуре файла, запускает `tesseract image stdout -l eng`, режет текст на
абзацы и сохраняет их как реплики — дальше они разбираются тем же
`/lines/{id}/explain`, с соседями. Через параметр `episodeId` снимки одной
игровой сессии складываются в один эпизод и дают друг другу контекст.
Без установленного Tesseract приложение запускается, а эндпоинт отвечает 503.
По умолчанию Tesseract ограничен одним потоком: в многопоточном режиме под
нагрузкой он замедлялся с 0,1 до 18 с на картинке ([`Recognition/OcrOptions.cs`](../../Recognition/OcrOptions.cs), комментарий к `ThreadLimit`).

## 3.5. Планирование повторений

Два планировщика за интерфейсом `IReviewScheduler`, выбор — `Review:Scheduler`
([`appsettings.json`](../../appsettings.json); по умолчанию `Fixed`).

**Лестница** ([`Review/FixedIntervalScheduler.cs`](../../Review/FixedIntervalScheduler.cs)):
1, 3, 7, 14, 30, 60, 120 дней; верный ответ — следующая ступень, ошибка — первая.

**Обучаемая модель забывания** ([`Review/HalfLifeRegression.cs`](../../Review/HalfLifeRegression.cs),
[`Review/AdaptiveScheduler.cs`](../../Review/AdaptiveScheduler.cs)) — half-life
regression [11]:

- вероятность вспомнить через `t` дней: `p = 2^(−t/h)`;
- период полураспада: `h = 2^(θ·x)`, признаки
  `x = [1, √верных, √ошибок, последний ответ — ошибка]`, `log2 h` ограничен [−4; 12];
- веса `θ` общие для элементов пользователя и обучаются онлайн-градиентным
  спуском по `(p − y)²` с L2-регуляризацией и ограничением градиента;
- веса не хранятся: при каждом решении модель заново проходит все ответы
  пользователя по порядку, поэтому веса — функция таблицы `ReviewEvent`;
- следующий показ — когда `p` упадёт до цели `T = 0,8`:
  `t = h · log2(1/T)`, округление до дней, ограничение [1; 365].

Модель сначала реализована в симуляции на Python ([`srs/`](../../srs/)), затем
перенесена в C#. На одних и тех же данных C#-версия совпадает с Python: в
100 прогонах из 100 совпали все 1 336 864 решения и прогнозы
([`srs/REPORT.md`](../../srs/REPORT.md), раздел «Проверка C#-планировщика»).
Для совпадения пришлось повторить суммирование с компенсацией ошибок
округления, как в `sum()` Python 3.12.

**Очередь показа.** У адаптивного планировщика `GET /review/next` выбирает
среди элементов со сроком тот, у которого выше предсказанная вероятность
забыть; у фиксированного — самый просроченный (`Review:QueueOrder`,
[`Review/ReviewOptions.cs`](../../Review/ReviewOptions.cs)). Причина — результат
симуляции при дневном лимите (глава 4).

**Отбор «i + 1».** Для показа выбирается реплика, где невыученным остаётся
только повторяемый элемент ([`Review/SingleUnknownSelector.cs`](../../Review/SingleUnknownSelector.cs)).

## 3.6. Пользователи и ограничения

JWT на 15 минут и refresh-токен на 30 дней с ротацией; в базе — только хеш
refresh-токена; повторное использование отозванного токена отзывает все
токены пользователя ([`Auth/`](../../Auth/)). Лимит дорогих запросов в
минуту на пользователя и суточная квота разборов ([`Quotas/`](../../Quotas/)).

## 3.7. Тестирование и CI

- 142 автотеста, все проходят ([`STATUS.md`](../../STATUS.md)). Приложение
  поднимается в памяти (`WebApplicationFactory`) с отдельной базой SQLite и
  подставными часами; внешние HTTP-сервисы подменяются обработчиком; картинки
  для распознавания рисуются в самом тесте.
- GitHub Actions: сборка и тесты с Tesseract, сборка Docker-образа и
  проверка распознавания в нём, сборка клиента на `windows-latest`
  ([`.github/workflows/ci.yml`](../../.github/workflows/ci.yml)).
- Десктопный клиент для Windows ([`client/`](../../client/)) — вспомогательная
  часть; результаты его проверки на раннере см. в `STATUS.md`.
