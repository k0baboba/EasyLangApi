# 4. Оценка

Оценка состоит из пяти частей: функциональная проверка, качество
объяснений, клиент, распознавание и планирование повторений. Для каждой указано,
откуда взяты числа и чего ещё нет.

Прогоны с настоящими сервисами шли на стандартных раннерах GitHub Actions:
Linux, 4 CPU, 15–16 ГБ памяти, без GPU ([`results:live/versions.txt`][versions],
[`results:results/eval/probe/environment.txt`][env]).

## 4.1. Функциональная проверка

- 142 автотеста проходят, в CI без пропусков ([`STATUS.md`](../../STATUS.md)).
- Сквозной поток «субтитры → разбор → словарь → повторение» проверен тестом
  `FlowTests` и вручную ([`STATUS.md`](../../STATUS.md), раздел V1).
- Разделение данных: второй пользователь не видит чужих эпизодов, реплик,
  элементов и показов, прямые id дают 404 (`IsolationTests`, `STATUS.md`, раздел V5).

## 4.2. Качество объяснений

### Живая проверка на `sample.srt`

Приложение с настоящими dictionaryapi.dev, Ollama (`qwen2.5:7b` на CPU) и
Tesseract, 8 фраз из одного эпизода ([`results:live/table.md`][live], коммит
`2daf1e5`). Результат качественный: выборка мала и выбрана вручную.

| Фраза | Словарь | Языковая модель с контекстом |
|---|---|---|
| `shift` | клавиша Shift — неверно | «устал… после двойной смены» — модель объяснила реплику целиком, а не слово |
| `beat` | «ветхий, потрёпанный» — неверно | «устал» — верно |
| `casing` | «упаковывать в коробку» — неверно | «обходил… осматривает место с целью преступления» — смысл верный, перевод неточный |
| `on the house` | 503 (словарь ответил 403) | «бесплатно» — верно, но в объяснении фраза на китайском |
| `no cap`, `pulling my leg`, `gonna`, `spill the beans` | 503 (словарь ответил 403) | смысл передан; часть объяснений на английском вместо русского |

Наблюдения, которые прямо видны в таблице:

1. Словарь без контекста ошибся во всех трёх однословных фразах из сцены.
   Это ожидаемо: он выбирает значение без сцены.
2. На раннере словарь ответил 403 на все выражения из нескольких слов,
   поэтому для них ответа словаря нет. Причина 403 не исследовалась `[ЗАМЕР]`.
3. Модель 7B на CPU давала верный смысл, но смешивала языки (китайские
   иероглифы, английский вместо русского) и в одном случае объяснила реплику
   вместо слова. Это довод за проверку формата ответа и за модель крупнее.
4. Время ответа: словарь 0,03–0,24 с, модель на CPU 22–41 с на фразу
   (там же, последний столбец). Для оверлея в игре 20–40 с неприемлемы;
   время на GPU или с облачной моделью `[ЗАМЕР]`.

### Сравнение на 150 фразах (eval)

Три варианта — словарь, модель без контекста, модель с контекстом — на
наборе из 150 фраз ([`eval/data/phrases.jsonl`](../../eval/data/phrases.jsonl)).
Модель разбора `qwen2.5:7b` на CPU, судья `llama3.1:8b`, который не видит
саму фразу. Все числа — из [`eval/RESULTS.md`](../../eval/RESULTS.md) и
[`eval/results/`](../../eval/results/).

Главное число — **слепая оценка** 120 случайных ответов: проверяющий не видел
ни варианта, ни вердикта судьи. Рядом — вердикт судьи на всех фразах.
В скобках — 95 % интервал Уилсона.

| Вариант | Слепая оценка, верно | Судья, верно |
|---|---:|---:|
| словарь | 13 из 40 = 32 % [20–48] | 63 из 146 = 43 % [35–51] |
| модель без контекста | 16 из 37 = 43 % [29–59] | 67 из 150 = 45 % [37–53] |
| **модель с контекстом** | **38 из 43 = 88 % [76–95]** | **133 из 150 = 89 % [83–93]** |

- Парное сравнение по судье (точный тест Макнемара): против модели без
  контекста только с контекстом верно 68 фраз, только без него — 2
  (p ≈ 4·10⁻¹⁸); против словаря — 72 против 4 (p ≈ 4·10⁻¹⁷).
- 25 контрольных фраз, где верен буквальный смысл: модель без контекста в
  9 из 25 выбрала сленговое прочтение, с контекстом — в 1, словарь — в 1 из 24.
  Контекст не только находит сленг, но и удерживает от ложного сленга.
- Согласие судьи со слепым проверяющим: 107 из 120 (89 %), каппа Коэна 0,78.
  Судья **завышает** оценки: 11 случаев «верно» против «неверно» у
  проверяющего, обратных — 2.

**На этом наборе гипотеза подтвердилась**: контекст сцены повышает долю
верных объяснений с 32–43 % до 88 % по слепой оценке. Ограничения, без которых
это число нельзя приводить (там же):

- фразы и правильные ответы сочинил автор эксперимента, носители их не проверяли;
- набор подобран так, чтобы контекст был важен, поэтому разница не описывает
  обычный текст;
- судья — языковая модель, слепой проверяющий — тоже модель (отдельный
  субагент), а не человек; проверки людьми не было;
- модель разбора одна, прогон один;
- в 8 из 150 ответов модели с контекстом есть иероглифы;
- 4 из 150 запросов к словарю закончились ошибкой 502 и не оценены;
- в слепой выборке 37–43 ответа на вариант, варианты не парные.

## 4.3. Клиент для Windows

Клиент проверен на раннере `windows-latest` с интерактивной сессией
(экран 1024×768) скриптом [`tools/client-check.ps1`](../../tools/client-check.ps1),
отчёт и снимки экрана — [`results:client/report.md`][client]. Удались все шаги:
вход, горячая клавиша Ctrl+Shift+E через SendInput, выбор области мышью,
распознавание («Are you gonna spill the beans No cap He counts the register»),
разбор выбранной фразы `spill the beans` и добавление в словарь. Шагов с
ошибкой — 0. Это проверка на раннере, а не на компьютере пользователя
во время игры; работа поверх полноэкранной игры — `[ЗАМЕР]`.

## 4.5. Планирование повторений

Источник всех чисел раздела — [`srs/REPORT.md`](../../srs/REPORT.md).
**Это симуляция с синтетическим учеником** и параметрами, подобранными
вручную: проверка механики, а не измерение на людях. 10 прогонов на
вариант, 180 дней.

### Без лимита повторений

При почти равной нагрузке (`adaptive@0.75`: 10 932 повторения против
10 837 у лестницы) к 180-му дню уверенно (p ≥ 0,9) помнится 522 слова
против 447 — на 17 % больше, во всех 10 прогонах из 10.

| Планировщик | Повторений | Слов с p ≥ 0,9 | Слов на 100 повторений |
|---|---:|---:|---:|
| лестница | 10 837 ± 148 | 447 ± 13 | 4,12 |
| HLR, T = 0,75 | 10 932 ± 278 | 522 ± 24 | 4,78 |
| HLR, T = 0,8 | 13 053 ± 459 | 612 ± 23 | 4,70 |
| HLR, T = 0,9 | 23 665 ± 978 | 827 ± 9 | 3,50 |

Доля верных ответов близка к цели (77 % при T = 0,75, 85 % при 0,85, 90 % при
0,9): модель откалибрована в среднем, хотя её форма не совпадает с «истинной»
памятью ученика.

### Лимит 60 повторений в день — отрицательный результат и его исправление

С очередью по дате адаптивный планировщик **проиграл** лестнице: 589 слов
против 593 при T = 0,8, а при высоких целях копил сотни просроченных слов.
Гипотеза: лимит тратится на самые просроченные, уже забытые слова. Проверка —
очередь по предсказанной вероятности забыть:

| Цель T | Слов с p ≥ 0,9: очередь по дате → по вероятности | Лучше лестницы (593) |
|---|---:|---:|
| 0,7 | 481 → 478 | 0 из 10 |
| 0,8 | 589 → 656 | 10 из 10 |
| 0,85 | 548 → 724 | 10 из 10 |
| 0,9 | 535 → 725 | 10 из 10 |

Гипотеза подтвердилась для T = 0,8–0,9 и не подтвердилась для T = 0,7. Очередь
по вероятности забыть стала порядком по умолчанию для адаптивного
планировщика в приложении.

### Данные реальных людей: Duolingo

Модель с признаками нашего планировщика обучена на открытых данных Duolingo
из работы Settles и Meeder [11]: 12 854 226 сессий, 115 222 пользователя;
обучение на первых 80 % по времени, проверка на последних 20 %
([`results:results/srs/results.md`][srs], [`srs/REPORT.md`](../../srs/REPORT.md)).

| Модель | MAE ↓ | AUC ↑ | ECE ↓ | Среднее p̂ |
|---|---:|---:|---:|---:|
| константа | 0,174 | 0,500 | 0,008 | 0,896 |
| одна экспонента для всех | 0,120 | 0,533 | 0,086 | 0,976 |
| логистическая регрессия (+ log(1 + Δ)) | 0,171 | 0,590 | 0,011 | 0,894 |
| **наш планировщик (HLR)** | **0,114** | **0,538** | 0,088 | 0,984 |

Доля верных ответов на проверке — 0,905.

Сравнение с таблицей 2 статьи (разбиение там 90/10, у нас 80/20, поэтому
сравнение приблизительное; таблицу выписал координатор из статьи):

| Модель в статье | MAE | AUC |
|---|---:|---:|
| HLR | 0,128 | 0,538 |
| HLR −lex (без признаков слов) | 0,128 | 0,537 |
| Leitner | 0,235 | 0,542 |
| Pimsleur | 0,445 | 0,510 |
| LR | 0,211 | 0,513 |
| константа p = 0,859 | 0,175 | — |

Выводы:

- Наш планировщик не использует признаки слов, поэтому сравнивать его надо с
  HLR −lex: AUC 0,538 против 0,537, MAE 0,114 против 0,128. **Реализация на
  уровне опубликованной.** Слабое различение (AUC около 0,54) — уровень метода
  на этих данных, а не дефект реализации.
- **Калибровка плохая**: среднее предсказание 0,984 при доле верных 0,905,
  ECE 0,088 против 0,008 у константы. В таблице статьи калибровки нет. Значит,
  на реальных данных обещание «цель T — это доля слов, которые вы будете
  помнить» не выполняется; калибровка из симуляции не подтвердилась.
- Логистическая регрессия с log(1 + Δ) дала AUC 0,590, LR в статье — 0,513.
  Это наблюдение, а не доказанное преимущество: разбиение и признаки другие.
