# 4. Оценка

Оценка состоит из четырёх частей: функциональная проверка, качество
объяснений, распознавание и планирование повторений. Для каждой указано,
откуда взяты числа и чего ещё нет.

Прогоны с настоящими сервисами шли на стандартных раннерах GitHub Actions:
Linux, 4 CPU, 15–16 ГБ памяти, без GPU ([`results:live/versions.txt`][versions],
[`results:results/eval/probe/environment.txt`][env]).

## 4.1. Функциональная проверка

- 142 автотеста проходят, в CI без пропусков ([`STATUS.md`](../../STATUS.md)).
- Сквозной поток «субтитры → разбор → словарь → повторение» проверен тестом
  `FlowTests` и вручную ([`STATUS.md`](../../STATUS.md), раздел V1).
- Разделение данных: второй пользователь не видит чужих эпизодов, реплик,
  элементов и показов, прямые id дают 404 (`IsolationTests`, `STATUS.md`, раздел V5).

## 4.2. Качество объяснений

### Живая проверка на `sample.srt`

Приложение с настоящими dictionaryapi.dev, Ollama (`qwen2.5:7b` на CPU) и
Tesseract, 8 фраз из одного эпизода ([`results:live/table.md`][live], коммит
`2daf1e5`). Результат качественный: выборка мала и выбрана вручную.

| Фраза | Словарь | Языковая модель с контекстом |
|---|---|---|
| `shift` | клавиша Shift — неверно | «устал… после двойной смены» — модель объяснила реплику целиком, а не слово |
| `beat` | «ветхий, потрёпанный» — неверно | «устал» — верно |
| `casing` | «упаковывать в коробку» — неверно | «обходил… осматривает место с целью преступления» — смысл верный, перевод неточный |
| `on the house` | 503 (словарь ответил 403) | «бесплатно» — верно, но в объяснении фраза на китайском |
| `no cap`, `pulling my leg`, `gonna`, `spill the beans` | 503 (словарь ответил 403) | смысл передан; часть объяснений на английском вместо русского |

Наблюдения, которые прямо видны в таблице:

1. Словарь без контекста ошибся во всех трёх однословных фразах из сцены.
   Это ожидаемо: он выбирает значение без сцены.
2. На раннере словарь ответил 403 на все выражения из нескольких слов,
   поэтому для них ответа словаря нет. Причина 403 не исследовалась `[ЗАМЕР]`.
3. Модель 7B на CPU давала верный смысл, но смешивала языки (китайские
   иероглифы, английский вместо русского) и в одном случае объяснила реплику
   вместо слова. Это довод за проверку формата ответа и за модель крупнее.
4. Время ответа: словарь 0,03–0,24 с, модель на CPU 22–41 с на фразу
   (там же, последний столбец). Для оверлея в игре 20–40 с неприемлемы;
   время на GPU или с облачной моделью `[ЗАМЕР]`.

### Пробный прогон оценки (eval)

Сравнение трёх вариантов — словарь, модель без контекста, модель с
контекстом — на наборе из 150 фраз ([`eval/data/phrases.jsonl`](../../eval/data/phrases.jsonl)),
судья — другая модель (`llama3.1:8b`). Пока выполнена только **проба на 5
фразах** ([`results:results/eval/probe/results.md`][probe]):

| Вариант | Верно | Точность [95 % ДИ Уилсона] |
|---|---:|---|
| словарь | 4 из 5 | 80 % [38–96] |
| модель без контекста | 5 из 5 | 100 % [57–100] |
| модель с контекстом | 5 из 5 | 100 % [57–100] |

На 5 фразах различия статистически не значимы (p = 1 по тесту Макнемара,
там же), а интервалы перекрываются почти полностью. **Выводов о пользе
контекста из пробы делать нельзя.** Полный прогон на 150 фразах — `[ЗАМЕР]`;
его оценка по времени — около 200 минут запросов ([`results:results/eval/probe/timing.md`][timing]).
Согласие судьи с человеком не проверено: подготовлена слепая выборка,
сама проверка — `[ЗАМЕР]`.

## 4.4. Планирование повторений

Источник всех чисел раздела — [`srs/REPORT.md`](../../srs/REPORT.md).
**Это симуляция с синтетическим учеником** и параметрами, подобранными
вручную: проверка механики, а не измерение на людях. 10 прогонов на
вариант, 180 дней.

### Без лимита повторений

При почти равной нагрузке (`adaptive@0.75`: 10 932 повторения против
10 837 у лестницы) к 180-му дню уверенно (p ≥ 0,9) помнится 522 слова
против 447 — на 17 % больше, во всех 10 прогонах из 10.

| Планировщик | Повторений | Слов с p ≥ 0,9 | Слов на 100 повторений |
|---|---:|---:|---:|
| лестница | 10 837 ± 148 | 447 ± 13 | 4,12 |
| HLR, T = 0,75 | 10 932 ± 278 | 522 ± 24 | 4,78 |
| HLR, T = 0,8 | 13 053 ± 459 | 612 ± 23 | 4,70 |
| HLR, T = 0,9 | 23 665 ± 978 | 827 ± 9 | 3,50 |

Доля верных ответов близка к цели (77 % при T = 0,75, 85 % при 0,85, 90 % при
0,9): модель откалибрована в среднем, хотя её форма не совпадает с «истинной»
памятью ученика.

### Лимит 60 повторений в день — отрицательный результат и его исправление

С очередью по дате адаптивный планировщик **проиграл** лестнице: 589 слов
против 593 при T = 0,8, а при высоких целях копил сотни просроченных слов.
Гипотеза: лимит тратится на самые просроченные, уже забытые слова. Проверка —
очередь по предсказанной вероятности забыть:

| Цель T | Слов с p ≥ 0,9: очередь по дате → по вероятности | Лучше лестницы (593) |
|---|---:|---:|
| 0,7 | 481 → 478 | 0 из 10 |
| 0,8 | 589 → 656 | 10 из 10 |
| 0,85 | 548 → 724 | 10 из 10 |
| 0,9 | 535 → 725 | 10 из 10 |

Гипотеза подтвердилась для T = 0,8–0,9 и не подтвердилась для T = 0,7. Очередь
по вероятности забыть стала порядком по умолчанию для адаптивного
планировщика в приложении.
