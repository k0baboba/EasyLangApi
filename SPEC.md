# EasyLangApi — спецификация прототипа

Учебный проект, основа для ВКР по теме «разработка интеллектуальных систем».

## Что это

Интеллектуальная система поддержки изучения иностранного языка. Пользователь
смотрит контент на английском, система разбирает незнакомые фразы **с учётом
контекста произведения** и возвращает их позже на повторение.

Ключевое отличие от переводчиков: в промпт уходит не изолированная строка,
а название произведения, соседние реплики и сцена. Поэтому система объясняет
сленг и регистр, а не переводит пословно.

## Что должен показать прототип

Сквозной поток: файл субтитров → разбор фразы с контекстом → сохранение
в словарь → выдача на повторение.

## Поток

1. `POST /episodes` — загрузка файла `.srt`, разбор на реплики с таймингами
2. `GET /lines/{id}/explain?phrase=...` — разбор фразы.
   В промпт идут: название эпизода, текущая реплика, две предыдущие и две следующие
3. Результат разбора сохраняется в базу
4. `GET /vocabulary` — список сохранённого
5. `GET /review/next` — следующий элемент на повторение
6. `POST /review/{id}` — ответ пользователя (помнил / не помнил), пересчёт интервала

## Модель данных

Ключевое решение: **фраза — единица показа, слово — единица учёта.**
Храним наблюдение и элемент знания отдельно.

```
Episode(id, title, source_file, created_at)
Line(id, episode_id, index, start_ms, end_ms, text)

Lookup(id, line_id, phrase, explanation_json, created_at)
  — наблюдение: что именно посмотрели и в каком контексте

KnowledgeItem(id, phrase_normalized, first_seen_at, interval_days, due_at, ease)
  — элемент учёта: что отслеживаем

ReviewEvent(id, knowledge_item_id, shown_at, answered_at, was_correct)
  — история ответов, НИЧЕГО не удалять и не агрегировать на входе
```

`ReviewEvent` — основа будущей адаптивной модели. Полнота этой таблицы важнее
всего остального в схеме.

## Разбор фразы

За интерфейсом, две реализации:

```csharp
public interface IPhraseExplainer
{
    Task<Explanation> ExplainAsync(string phrase, PhraseContext context);
}
```

- `DictionaryExplainer` — через `https://api.dictionaryapi.dev/api/v2/entries/en/{word}`,
  бесплатно, без ключа. **Рабочая реализация по умолчанию.**
- `LlmExplainer` — запрос к языковой модели с контекстом.
  Написать, но включать только если задан ключ в конфигурации.
  Без ключа приложение должно запускаться и работать на первой реализации.

`PhraseContext` — все поля необязательные: `Title`, `Speaker`, `Before`, `After`.
Сборщик промпта использует то, что пришло, и деградирует плавно.

## Стек

- .NET 10, ASP.NET Core minimal API
- EF Core + **SQLite** (файл, без Docker и без сервера)
- Миграции EF, база создаётся при первом запуске
- xUnit для тестов

## Версии

Выполняй версии строго по порядку, в одной ветке. К следующей версии переходи,
только когда текущая отвечает своему критерию. Каждая версия добавляет код,
не ломая предыдущую. Всё, что описано выше, — это версия 1.

Коммить и пушь после каждого рабочего шага, чтобы результат не потерялся,
если сессия оборвётся. Веди `STATUS.md`: что готово, что проверено запуском,
что написано, но не проверено, что не успели.

### V1. Ядро

Весь поток из раздела «Поток» на словаре, без ключей к внешним сервисам.

Готово, когда: с чистого клона `dotnet run` поднимает приложение, база создаётся
сама, эндпоинты отвечают, тесты проходят. В репозитории есть `sample.srt`,
`requests.http` и `README.md`.

**V1 важнее всех остальных версий вместе. Нельзя начинать V2, пока V1 не готова.**

### V2. Распознавание текста

- `ITextRecognizer` и реализация на Tesseract
- `POST /recognize`: изображение на входе, распознанный текст на выходе
- Распознанный текст идёт в тот же поток разбора через общий `ITextSource`
- Тесты на изображениях, которые генерируются в самом тесте

Готово, когда: распознавание работает на тестовых изображениях. Если Tesseract
не установлен, приложение всё равно запускается, а эндпоинт возвращает понятную ошибку.

### V3. Языковая модель

- `LlmExplainer` работает с любым API, совместимым с OpenAI: адрес, модель и ключ
  задаются в конфигурации, поэтому подходят и внешний сервис, и локальный Ollama
- Тесты сборщика промпта и разбора ответа на подставном HTTP-клиенте

Готово, когда: тесты проходят без настоящего ключа. Без настройки приложение
работает на `DictionaryExplainer`.

### V4. Планировщик повторений

- `IReviewScheduler` с реализациями на фиксированных интервалах и адаптивной,
  которая оценивает вероятность забывания по `ReviewEvent`
- Планировщик выбирается в конфигурации
- Отбор фраз, в которых незнакомый элемент ровно один

Готово, когда: оба планировщика покрыты тестами. Папку `srs/` не трогай: она
принадлежит отдельной сессии и не должна быть зависимостью основного приложения.

### V5. Пользователи и квоты

- Регистрация и вход, JWT и refresh-токены
- Данные разделены по пользователям
- Лимит запросов к дорогим эндпоинтам

Готово, когда: тесты проходят, а чужие данные недоступны.

### V6. Docker и CI

- `Dockerfile` с Tesseract
- `docker-compose` с приложением и опциональным Ollama
- GitHub Actions: сборка и тесты

Готово, когда: сборка и тесты описаны в CI. Если Docker в среде недоступен,
честно отметь это в `STATUS.md` как непроверенное.

### V7. Десктопный клиент

Папка `client/`, простой клиент для Windows: хоткей, захват области экрана, отправка
на сервер, показ ответа. Вся логика остаётся на сервере.

Облачная среда не может запустить такой клиент, поэтому в `STATUS.md` он должен
быть отмечен как не проверенный на Windows. Основное решение не должно зависеть
от его сборки.

## Что не делать ни в одной версии

- Веб-фронтенд
- Публичный деплой и платежи
- Микросервисы

## Правила автономной работы

Владелец недоступен. Не жди ответов на вопросы: выбирай простое решение и записывай
его в `STATUS.md`. Не выдавай написанное за проверенное: «работает» можно писать
только о том, что запускалось в этой сессии.
